# Execution plan: Step 9, `publish`

## Goal

Ship Step 9 of the spec's Implementation Plan: `publish` pushes exactly the snapshot in `<out>` as a one-commit GitHub template repository, through the eight publication steps (verify, auth, repo state, local commit, create, push, template-flag, topics), with the approval prompt (Q11), `publication.json` rewritten after each step, `retry` and `--resume`.

## Scope

- `src/publish.ts`: `verify` (lstat, `O_NOFOLLOW` reads, path set, size, sha256, exec bit, `snapshotId`, `--expect`, report errors; rule `snapshot-modified` with `reason`), the prompt (Q11, counts from the verified tree, default no, `publish-declined`), the Git check, auth (`gh auth status`, exit 3), repo read (`gh api repos/<o>/<r>`, 404 only means missing, any other failure exit 4 `create`/`repo-read`), `repo-name-exists`, `visibility-mismatch`, the local commit (`git init --template=`, `hash-object -w --no-filters --stdin`, `update-index --index-info`, `write-tree`, tree check, `commit-tree --no-gpg-sign`, noreply identity from `gh api user`, fixed message), `create`, `push` (clone `--no-checkout`, empty or matching or `repo-not-from-snapshot`, fetch from the build repo, push without force through `gh auth git-credential`, `workflow-scope`), `template-flag` (`PATCH -F is_template=true`, checked), `topics` (`--add-topic`), `publication.json` after each step, `retry`.
- `src/cli.ts`: `publish` dispatched with `--from`, `--repo`, `--public`/`--private`, `--expect`, `--resume`, `--json`; usage checks (exit 2) before any Git read or GitHub call; envelope fields `snapshotId`, `repo`, `commit`, `steps`, `retry`. `describe` keeps exit 2 "not implemented yet".
- `test/release-e2e/gh-shim.mjs`: copied from `create-mercato-module` main 5b7849cca6a3cd6207bdcf836ff285344afc1dd7, extended only with `api --method PATCH repos/<o>/<r>`, `visibility` in the `repos/<o>/<r>` answer and a log of every mutating call; source recorded in `test/release-e2e/SOURCE.md`.
- Tests: `test/publish.test.cjs` with every case named under Step 9, against the shim and local bare repositories only, user Git config isolated (`HOME`, `GIT_CONFIG_GLOBAL`), a fake token asserted absent from every output and file.
- Docs: `docs/guide.md`, `--help`, `CHANGELOG.md` (Unreleased), `AGENTS.md` status and routing, README status line.

## Non-goals

- Step 10 and later: `describe` keeps exiting 2 "not implemented yet"; no release-checks job.
- No change to `prepare`, the `snapshotId` algorithm or the report schema.

## Risks

- A remote change before `verify` or auth: the order is enforced in code and asserted by tests through the shim's mutation log.
- A token leaking: the tool never reads one; the push uses `gh auth git-credential`; tests set a fake `GH_TOKEN` and scan every output and file.
- Failure injection (push refused once, `repo create` failing once, workflow scope) is done outside the shim: a pre-receive hook in the bare repository, and a test-only `gh` wrapper that fails one command once before handing over to the shim, so the shim keeps only the extensions the spec lists.
