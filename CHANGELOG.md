# Changelog

## Unreleased

- New CLI skeleton: `--help` and `--version` work. `prepare`, `publish` and `describe` exit with code 2 and say they are not implemented yet, so scripts can rely on the exit codes from the start.
- New argument parser (spec Step 1): every flag of the three commands is known. An unknown command or flag, a flag on the wrong command, a missing value, a repeated flag (except `--allow-file` and `--keep-env`) and both `--public` and `--private` exit 2. `--help` and `-h` win over every other problem, but never count as a flag value (`describe --summary --help`). `--version` works only on its own.
- New `--json` output: with a command, stdout carries exactly one JSON object (schema 1: `schema`, `command`, `ok`, `exitCode`, `tool`, `failures`), also for usage errors and unexpected errors (rule `internal`, exit 1, no stack trace).
- New Git check for the commands that read Git: Git 2.40 or newer (`git-version`), `git` on `PATH` (`git-missing`) and Git's "dubious ownership" refusal (`git-unsafe-directory`), each exit 1 with a hint.
- New stock table (spec Step 2): `src/stock/table.json` records, for every stable `create-mercato-app` version from 0.4.5 to 0.9.0, the stock `.env.example`, each key's stock values, the credential URLs of the scaffold files and the stock README hash. Lookups by the pinned `@open-mercato/core` version; an unknown version matches any known version and reports `known: false`. The commands start using it in later steps.
- New maintainer script `npm run stock-table` (`scripts/build-stock-table.mts`, not shipped) adds the missing stable versions from npm; `--check` only lists them. A weekly `Stock table` workflow fails when npm has a stable version the table lacks; it never runs on pull requests.
- New snapshot core of `prepare` (spec Step 3), behind an internal entry point that tests call; the `prepare` command still exits 2 "not implemented yet" and writes nothing until Step 8. It pins `HEAD` once, exports the files of that commit as Git stores them, leaves out `export-ignore` files and the catalog deny list (`.env*` files, `node_modules/`, `/data/`, agent state and more) before reading them, and refuses symlinks, submodules, unsafe paths, paths that differ only in case and Git LFS pointers. Uncommitted changes are always listed and exported only with `--include-uncommitted`, read without following symlinks. It writes `<out>/tree/` and `report.json` with `snapshotId`, or only `report.json` when there is an error. No Git hook, file system monitor or filter of the app runs, and the app is never written.
- `--out` must not be inside the app, judged by real paths: a `--out` reached through a symlink into the app, or one that does not exist yet below such a symlink, is refused (exit 2).
- New root checks in the `prepare` entry point (spec Step 4), still behind the internal entry point until Step 8. A snapshot is refused when it is not an Open Mercato app on Yarn 4: no readable `package.json`, no `@open-mercato/core` dependency, the framework monorepo itself, a `packageManager` other than `yarn@4.x`, no `yarn.lock` (or a Yarn 1 one), an `@open-mercato/*` package missing from `yarn.lock` or a `yarn.lock` out of date with `package.json`, Open Mercato framework packages on more than one `major.minor` line (packages released on their own line, such as `@open-mercato/client`, do not count), or a file ending in `.template`. Root `workspaces` is a warning only. The report now names the pinned Open Mercato version (`openMercato`), the matching stock table entry (`stock`), `engines`, `packageManager` and whether the lockfile resolves `@open-mercato/enterprise` (`enterprise.dependency`, never blocking).
- New runtime dependency `yaml` 2.9.1, pinned exactly, to read Yarn 4 lockfiles.
- New module inventory and manifest in the `prepare` entry point (spec Step 5), still behind the internal entry point until Step 8. The modules the app registers are read from `src/modules.ts` with the TypeScript parser, without running app code: the exported module list, later `push`, `unshift` and spread additions, and the loop over the official modules of `src/official-modules.generated.ts` (first entry per id kept). A conditional registration gets a `when` (`OM_ENABLE_STORAGE_S3`, `OM_ENABLE_ENTERPRISE_MODULES && OM_ENABLE_ENTERPRISE_MODULES_SSO`, `module:example`, or `custom` for a condition outside that grammar). A missing `src/modules.ts` or one with a syntax error is an error (`modules-ts`); a construct the reader cannot follow is a warning with its line (`modules-unparsed`), never dropped silently; a `from` that is neither `@app` nor an npm name is a warning (`module-from-unknown`). Each npm module gets the `package` version `yarn.lock` resolves; none is an error for an unconditional module and a warning for a conditional one (`module-package-unresolved`).
- `prepare` now writes `mercato-template.json` into the snapshot (`name`, `description`, `openMercato`, `modules`, `createdWith`; `env` comes in Step 8), replacing one from the app, with the warnings `manifest-name` and `manifest-description`. The report gains `modules {entries, unparsed}` and `enterprise.modules`. Because the export now holds the generated manifest, the `snapshotId` of an unchanged app differs from the one Step 4 computed.
- New bundled secret rules (spec Step 6): `src/rules/gitleaks.json` holds the 222 default rules of gitleaks v8.30.1, converted for JavaScript from its `config/gitleaks.toml` (pinned by tag and sha256), with their path filters and allowlists (`regexTarget`, `condition`, `AND` paths); path-only and global allowlists are dropped, so every exported file is scanned. The `prepare` entry point records them in `report.tool.rules {source, count, skipped}`. The scan that uses them comes in Step 7; the `prepare` command still exits 2 until Step 8.
- New maintainer script `npm run secret-rules` (`scripts/build-secret-rules.mts`, not shipped) fetches the pinned config, converts it and fails on any rule it cannot convert unless `scripts/secret-rules-skipped.json` lists it with a reason, or when a required rule such as `private-key` or `github-pat` is missing; `--check` compares with the committed file. No new dependency: TOML is read by a small strict reader inside the script.
- New secret scan and opaque file check in the `prepare` entry point (spec Step 7), still behind the internal entry point until Step 8. Every exported text file, the generated `mercato-template.json` included, is scanned with the bundled gitleaks rules and extra rules (OpenAI keys without the `T3BlbkFJ` marker, Stripe `whsec_` webhook secrets, and the `create-mercato-module` credential pattern as a floor); a match is an error, `secret`, with `ruleId` and `line`, and has no override. A connection URL with a literal password is `credential-url`, except the exact stock URLs of any known `create-mercato-app` version and passwords that are only `$NAME` or `${NAME}`. `npmAuthToken` or `npmAuthIdent` in `.yarnrc.yml` is `yarn-auth`. A file that is not text, or an image or font whose content does not match its extension, or an archive or database file, is `opaque-file` unless the entry point's `allowFiles` option names it (the `--allow-file` flag comes in Step 8); an unused `allowFiles` path is the warning `allow-file-unused`. The report gains `allowFiles [{path, used}]`, and no finding or report field ever holds a matched value.
- `prepare` works on the command line (spec Step 8): `npx create-mercato-template prepare [<app>] --out <dir>` with `--include-uncommitted`, `--allow-file <path>` (repeatable), `--keep-env <KEY>` (repeatable) and `--json`. It exits 0 with `<out>/tree` and `report.json`, or 1 with only `report.json` when there is an error. Without `--json` it prints a summary of the errors, warnings and notices on stdout (and one error line on stderr on exit 1); with `--json` it prints one envelope that adds `out`, `snapshotId` and `report`, and lists every error finding under `failures`. A missing `--out` or a `--keep-env` value that is not a key name is exit 2. `publish` and `describe` still exit 2 "not implemented yet".
- `prepare` now regenerates the root `.env.example` (no longer excluded): a value is kept only when it is a stock value of its key for the app's `create-mercato-app` version (any known version when the version is unknown), or when `--keep-env` names a key that does not look secret and the value passes the secret scan; every other value is emptied (`KEY=`). `report.env` lists the `kept`, `emptied` and `declared` keys and the `dropped` lines, never a value. A value that is emptied, or a line that is dropped, is still checked with the secret rules: a credential committed to `.env.example` is an error. New rules: `env-keep-secret` and `env-keep-unknown` (errors), `env-line-dropped`, `env-undocumented`, `env-example-missing` and `nested-env-example` (warnings). Keys the stock file lacks are declared in `mercato-template.json` `env`, with the comment above each key as its description and the first `https://` URL as its link; a `mercato-template.json` from the app supplies them for a key without a comment.
- New review warnings: `image` (every image, with sizes in the new `report.images`), `executable-config` (`.yarnrc.yml` `yarnPath` or `plugins`, GitHub workflows, `package.json` install and publish scripts), `ai-content` (files under `.ai/`), `seed-email` (an address outside the example domains in a seed file, reported by path and line only), `readme-missing`, `readme-stock` and `exceeds-import-limits` (more than 5,000 files or 50 MB). New notices: `stock-unknown`, `enterprise-dependency` and `derived-from-template`. The `checks-incomplete` notice is gone. Because the export now holds the generated `.env.example`, the `snapshotId` of an unchanged app differs from the one Step 7 computed.
- `publish` works (spec Step 9): `npx create-mercato-template publish --from <dir> --repo <owner/name> (--public | --private)` with `--expect <snapshotId>`, `--resume` and `--json`. It checks `<dir>` against its `report.json` first (rule `snapshot-modified` with a `reason`, exit 1, nothing remote), asks for approval on a terminal when `--expect` is not given (no is `publish-declined`; without a terminal or with `--json`, `--expect` is required, exit 2), checks `gh auth status` (exit 3), reads the repository once (`repo-name-exists`, `visibility-mismatch`), builds the one commit locally (author and committer: the account's noreply address, never signed), then creates the repository, pushes the commit to `main` (never forced), marks it as a template and adds the `open-mercato-template` and `open-mercato` topics. `<dir>/publication.json` is rewritten after each step. A failed GitHub step is exit 4 with the steps, `repo`, `commit` and a `retry` command; `--resume` continues on a missing, empty or matching repository and refuses any other (`repo-not-from-snapshot`). A push refused for the `workflow` scope says to run `gh auth refresh -s workflow`. No token is read or printed.
- New test stand-in `test/release-e2e/gh-shim.mjs`, copied from `create-mercato-module` and extended with `api --method PATCH repos/<o>/<r>`, a `visibility` field and a log of every mutating call.
- `describe` works (spec Step 10): `npx create-mercato-template describe --from <dir>` prints the catalog entry `templates/<owner>/<repo>.yml` (YAML, `github` and the path in lower case) and the CONTRIBUTING link of Open Mercato Modules, with `--repo`, `--use-case`, `--summary`, `--when-to-use`, `--when-not-to-use` and `--json`. The repository comes from `<dir>/publication.json` or `--repo`; `summary` defaults to the manifest description when it is plain text of 20 to 140 characters; `declares.env` lists the keys the manifest declares, never a value. A missing required value is printed as a YAML comment, and the entry is marked incomplete (`complete: false`, `missing`) with exit 0. Text flags are checked as the catalog checks descriptors (plain text, lengths, `Use when ` prefix) and refused when they hold an email address or match the secret scan (exit 2). A missing report, a report with errors or a changed manifest is exit 1, rule `snapshot-modified`. Error messages of every command are now redacted like `internal` ones, so an email address or a token typed in a flag or a path is never printed. It reads only `<dir>`: no network, no GitHub call, no write. No command answers "not implemented yet" any more.
- New draft `test/fixtures/catalog/template-1.json`, written from the catalog spec until the catalog publishes the schema; the release waits for the published file.
