# create-mercato-template

A Node CLI (`npx create-mercato-template`) that saves an Open Mercato app as a clean GitHub template repository. Three commands: `prepare` builds a reviewed snapshot of one pinned commit, offline and without running app code; `publish` pushes exactly that snapshot as a one-commit template repository; `describe` prints the catalog entry. TypeScript compiled to CommonJS in `dist/`. The only runtime dependency today is `typescript` (6.0.3, exact); the spec adds `yaml` (2.9.1, exact) in Step 4. The design is `.ai/specs/2026-10-30-create-mercato-template.md` (Phase 2 of the catalog spec in `open-mercato/modules`); build it step by step from its Implementation Plan.

Status: only `--help` and `--version` are implemented. Files marked "(planned)" below do not exist yet; create them in the spec step that names them.

## Task routing

| When the task involves… | Read first | Key rules |
|---|---|---|
| CLI arguments, flags, exit codes, the `--json` envelope | `src/cli.ts`, `docs/guide.md` | Flags are parsed by hand; unknown flags, flags on the wrong command and missing values are exit 2. Every flag is documented in the help text and the guide. Exit codes 0-4 are a contract: throw a `CliError` with its code, never let a failure fall back to 1 silently. With `--json`: one object on stdout, nothing else, no prompts. |
| Running external commands | `src/common.ts` (planned, copied from `create-mercato-module`) | `run`/an `Executor` with argument arrays, never a shell string. Captured network commands keep the default timeout. |
| Snapshot export | `src/git.ts`, `src/snapshot.ts` (planned) | Pin `HEAD` once and read blobs of that sha; never the working tree unless `--include-uncommitted`. No Git command that writes runs on the source app (`GIT_OPTIONAL_LOCKS=0`). The `snapshotId` algorithm is a protected surface. |
| File policy and secret scan | `src/policy/*.ts`, `src/rules/` (planned) | Deny list before any read. Findings print `rule`, `path` and `line`, never the matched value. No override for a secret finding. |
| Stock table and bundled gitleaks rules | `src/stock/table.json`, `src/rules/gitleaks.json`, `scripts/*.mts` (planned) | Generated by the scripts and committed; never hand-edited. |
| Manifest and module inventory | `src/manifest.ts`, `src/inventory.ts`, `src/lockfile.ts` (planned) | `mercato-template.json` schema is owned by the catalog (`mercato-template-1.json`). The inventory follows the catalog's `modulesFromModulesTs` rules, kept aligned by a contract test. Static reads only. |
| Publication | `src/publish.ts` (planned) | `verify` before auth, auth before any remote step. Explicit `--public`/`--private`. The commit is built locally before any remote change. Never force-push, never delete or rewrite a repository. `--resume` only on an empty repository or one made from this snapshot. |
| Describe | `src/describe.ts` (planned) | Output validates against the catalog's `template-1.json`. No network. |
| Unit tests | `test/*.test.cjs` | `node --test` against `dist/`; external commands are replaced with fake executors, local bare Git repositories or a `gh` shim. No test touches github.com or npmjs.com. Secret-looking fixtures are generated at test time, not committed. |
| Release checks (save then import) | `test/release-e2e/README.md` (planned, Step 9) | Separate from unit tests; never creates real repositories or publishes packages. |

## Validation

Run in order: `npm run typecheck`, `npm test`, `npm pack --dry-run`. CI also runs `npm run lint`.
