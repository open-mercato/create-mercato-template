# create-mercato-template

A Node CLI (`npx create-mercato-template`) that saves an Open Mercato app as a clean GitHub template repository. Three commands: `prepare` builds a reviewed snapshot of one pinned commit, offline and without running app code; `publish` pushes exactly that snapshot as a one-commit template repository; `describe` prints the catalog entry. TypeScript compiled to CommonJS in `dist/`. The runtime dependencies are `typescript` (6.0.3, exact) and `yaml` (2.9.1, exact, added in spec Step 4 for the Yarn 4 lockfile); keep both pinned without a caret. The design is `.ai/specs/2026-10-30-create-mercato-template.md` (Phase 2 of the catalog spec in `open-mercato/modules`). Build it step by step from its Implementation Plan.

Status: `--help`, `--version`, the argument parser, the `--json` envelope and the Git check (`src/git.ts`, `checkGit`) are implemented (spec Step 1), and so is the stock table (`src/stock.ts`, `src/stock/table.json`, `scripts/build-stock-table.mts`, spec Step 2), and so is the snapshot core behind the internal entry point `prepare()` (`src/prepare.ts`, `src/snapshot.ts`, `src/policy/deny.ts`, `src/policy/entries.ts`, spec Step 3; tests call it directly), and so are the root checks and the Yarn lockfile reader inside it (`src/policy/root.ts`, `src/lockfile.ts`, spec Step 4), and so are the module inventory and the generated manifest inside it (`src/inventory.ts`, `src/manifest.ts`, spec Step 5), and so are the bundled gitleaks rules and `report.tool.rules` (`scripts/build-secret-rules.mts`, `scripts/secret-rules-skipped.json`, `src/rules/gitleaks.json`, `src/rules/gitleaks.ts`, spec Step 6), and so are the secret scan, the opaque file check and the `allowFiles` option inside it (`src/policy/secrets.ts`, `src/policy/opaque.ts`, `src/rules/extra.ts`, spec Step 7), and so are the env diff with the generated `.env.example`, `--keep-env`, the declared env in the manifest, the review warnings and notices, and `prepare` on the CLI with its flags and `--json` envelope (`src/policy/env.ts`, `src/policy/warnings.ts`, `src/version.ts`, `src/cli.ts` `runPrepare`, spec Step 8), and so is `publish` with its eight steps, the prompt (Q11), `publication.json`, `retry` and `--resume`, on the CLI with its flags and `--json` envelope (`src/publish.ts`, `src/cli.ts` `runPublish`, `test/release-e2e/gh-shim.mjs`, spec Step 9), and so is `describe` with the catalog entry YAML, the CONTRIBUTING link, its flags and `--json` envelope (`src/describe.ts`, `src/cli.ts` `runDescribe`, `test/fixtures/catalog/template-1.json`, spec Step 10), and so is the save then import contract test with its `release-checks` CI job (`test/release-e2e/local.mts`, `test/release-local.test.cjs`, spec Step 11). Version 0.1.0 is prepared for the first release (spec Step 12): the vendored catalog schemas and `modulesFromModulesTs` fixtures are the catalog's generated files, and the contract test runs. It is not on npm yet; publishing to npm is a maintainer's step, never an agent's. Until then the commands run from GitHub (`npx --package github:open-mercato/create-mercato-template create-mercato-template <command>`). Files marked "(planned)" below do not exist yet; create them in the spec step that names them.

## Task routing

| When the task involves… | Read first | Key rules |
|---|---|---|
| CLI arguments, flags, exit codes, the `--json` envelope | `src/cli.ts`, `docs/guide.md`, `test/cli.test.cjs`, `test/prepare-cli.test.cjs` | Flags are parsed by hand from the `flags` matrix in `src/cli.ts`; unknown flags, flags on the wrong command, missing values and repeated non-repeatable flags are exit 2. `main()` never throws: it prints and returns the exit code. Every flag is documented in the help text and the guide. Exit codes 0-4 are a contract: throw a `CliError` with its code, never let a failure fall back to 1 silently. With `--json`: one object on stdout, nothing else, no prompts. A command reports through an `Outcome` (exit code, `failures`, its envelope fields, the text printed without `--json`); `prepare` lists every `error` finding under `failures`. `toolVersion` lives in `src/version.ts`, so modules that `src/cli.ts` imports never import `src/cli.ts`. |
| Running external commands | `src/common.ts` (copied from `create-mercato-module`) | `run`/an `Executor` with argument arrays, never a shell string. Captured network commands keep the default timeout. |
| Snapshot export | `src/git.ts` (`GitReader`), `src/snapshot.ts`, `src/prepare.ts` | Pin `HEAD` once and read blobs of that sha; never the working tree unless `--include-uncommitted`, and then only with `O_NOFOLLOW` and the parent `realpath` check. No Git command that writes runs on the source app, and no `git status` (`GIT_OPTIONAL_LOCKS=0`, `-c core.fsmonitor=false`, `-c core.hooksPath=/dev/null`). Paths stay bytes until `unsafe-path` has checked them. The `snapshotId` algorithm is a protected surface. |
| File policy and secret scan | `src/policy/*.ts` (`deny.ts`, `entries.ts`, `root.ts`, `secrets.ts`, `opaque.ts`, `env.ts`, `warnings.ts`), `src/rules/gitleaks.ts`, `src/rules/extra.ts`, `test/secrets.test.cjs`, `test/env.test.cjs`, `test/warnings.test.cjs`, `test/helpers/secret-fixtures.cjs`, `test/helpers/stock-app.cjs` | Deny list before any read; only the root `.env.example` is excepted from `**/.env*`, and it is never exported as it is: `src/policy/env.ts` regenerates it. No env value enters a finding, message or report field (`report.env` holds key names and line numbers only), and a seed email is reported by path and line only. Findings print `rule`, `path`, `line` and `ruleId`, never the matched value; a matched value stays inside `src/policy/secrets.ts`. No override for a secret finding (no `gitleaks:allow`). The matcher follows gitleaks v8.30.1 `detect.go`; extra rule ids are part of the report, never renamed. Test fixtures that look like secrets are assembled from parts at test time. |
| Stock table and bundled gitleaks rules | `src/stock.ts`, `src/stock/table.json`, `scripts/build-stock-table.mts`, `src/rules/gitleaks.json`, `scripts/build-secret-rules.mts`, `scripts/secret-rules-skipped.json`, `test/fixtures/gitleaks/SOURCE.md` | Generated by the scripts and committed; never hand-edited (except `scripts/secret-rules-skipped.json`, the maintainer's list of rules left out, each with a reason). Scripts run with Node's type stripping and import only `src/*.ts` modules without relative imports by their `.ts` names (`src/common.ts`, `src/env-file.ts`, `src/stable-version.ts`, `src/policy/credential-url.ts`); a type-only import of any `src/` module is fine, it is erased. Network only in a maintainer's run (`npm run stock-table`, `npm run secret-rules`); tests use fixtures and fake executors. A gitleaks pattern construct with no translation fails the build; never pass one through. |
| Manifest and module inventory | `src/manifest.ts`, `src/inventory.ts`, `src/lockfile.ts`, `test/fixtures/scaffold/SOURCE.md`, `test/fixtures/catalog/SOURCE.md` | `mercato-template.json` schema is owned by the catalog (`mercato-template-1.json`); the vendored copy is the file the catalog generates, byte for byte (source commit and sha256 in `test/fixtures/catalog/SOURCE.md`); copy it again from the catalog, never edit it. The inventory follows the catalog's `modulesFromModulesTs` rules, kept aligned by a contract test on the vendored catalog fixtures (`test/fixtures/catalog/modules-from-modules-ts/`, `{entries, unparsed}`). When the tool and a fixture disagree, the spec decides: fix the tool, or report the fixture to the catalog; never edit a fixture to pass. Static reads only: the `typescript` parser, no type checking, no app code run. Vendored scaffold files stay byte for byte. |
| Publication | `src/publish.ts`, `test/publish.test.cjs`, `test/release-e2e/gh-shim.mjs`, `test/release-e2e/SOURCE.md`, `test/helpers/gh-wrapper.mjs` | `verify` before auth, auth before any remote step. Explicit `--public`/`--private`. The commit is built locally before any remote change. Never force-push, never delete or rewrite a repository. `--resume` only on an empty repository or one made from this snapshot. Push only the bytes `verify` read; author and committer are the `gh` account's noreply address, never the Git identity; `commit-tree --no-gpg-sign`. No token is read, written or printed: Git gets it from `gh auth git-credential`. The shim keeps only the extensions spec Step 9 lists (PATCH `repos/<o>/<r>`, `visibility`, the mutation log); failure injection lives in the test wrapper or in a bare repository's `pre-receive` hook, never in the shim. |
| Describe | `src/describe.ts`, `test/describe.test.cjs`, `test/fixtures/catalog/template-1.json`, `test/fixtures/catalog/SOURCE.md` | Output validates against the catalog's `template-1.json` (the file the catalog generates, vendored byte for byte). Read-only: reads `<from>` only, no network, no GitHub call, no other program, no write outside stdout. Every text that reaches the output is plain text with no email address and no secret-scan match; a bad flag is exit 2 without its value in the message. Author fields only: never a curator field, `smoke` or a `/submit` link before catalog Phase 1b. |
| Unit tests | `test/*.test.cjs`, `test/helpers/fixture-app.cjs`, `test/helpers/json-schema.cjs` | `node --test` against `dist/`; Git tests build fixture repositories in a temp directory from `test/helpers/fixture-app.cjs` (isolated Git config, no network); external commands are replaced with fake executors, local bare Git repositories or a `gh` shim. No test touches github.com or npmjs.com. Secret-looking fixtures are generated at test time, not committed. The JSON Schema helper throws on a keyword it does not know; teach it the keyword, with a test in `test/json-schema.test.cjs`, rather than strip it from a schema. |
| Release checks (save then import) | `test/release-e2e/README.md`, `test/release-e2e/local.mts`, `test/release-e2e/SOURCE.md`, `test/release-local.test.cjs`, `.github/workflows/test.yml` (`release-checks`) | Separate from unit tests (`npm run test:release:local`); never creates real repositories, calls the real GitHub API or publishes packages. `publish` goes to the gh shim; the import reads it through the API stand-in on 127.0.0.1 only, with a fetch guard. The job keeps `permissions: contents: read`, no secrets, triggers `pull_request`, `push` to `main` and `workflow_dispatch` only, and a Postgres password generated per run (`test/release-local.test.cjs` checks these). The fake `.env` key is made at run time. Never weaken an assertion to make the `@latest` leg pass: report upstream drift. |
